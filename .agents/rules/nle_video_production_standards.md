# NLE Video Production & Post-Production Engineering Standards

All video editing, timeline assembly, color grading, audio post-production, and XML interchange generated by agents in this repository must strictly adhere to these standards.

---

## 1. Timebase & Timecode Rational Mathematics

- **Rational Fractional Representation**: All timestamps, cut points, durations, and marker offsets in interchange formats (FCPXML, EDL, OTIO) must be expressed as exact rational fractions:
  - **24.000 fps**: `1/24s` (or `100/2400s`)
  - **23.976 fps (24000/1001)**: `1001/24000s`
  - **29.970 fps (30000/1001)**: `1001/30000s`
  - **30.000 fps**: `1/30s` (or `100/3000s`)
  - **59.940 fps (60000/1001)**: `1001/60000s`
  - **60.000 fps**: `1/60s` (or `100/6000s`)
- **Prohibition of Floating-Point Drift**: Never encode durations as imprecise floats (e.g. `duration="3.33333s"`). Timecode rounding errors compound across long timelines, causing audio-video drift. Always use integer numerator/denominator pairs.

---

## 2. Color Science & Pipeline Governance

- **Color Space Workflows**:
  - **Rec.709 / sRGB**: Standard Dynamic Range (SDR) delivery for YouTube, web, and social platforms with gamma 2.4.
  - **Apple Log**: 10-bit log gamma captured on iPhone 15/16 Pro. Must be mapped using official Apple Log-to-Rec.709 LUT or Color Space Transform (CST) before grading.
  - **DaVinci Wide Gamut (DWG) / Intermediate**: Preferred wide-gamut timeline space for Resolve projects.
  - **ACES (ACEScc / ACEScct)**: Required for multi-camera color management across diverse sensors (Sony S-Log3, Canon Log, ARRI LogC, Apple Log).
- **Node Graph Hierarchy**:
  ```
  [Input / CST] ──> [Exposure / Contrast] ──> [White Balance] ──> [Secondary / Isolation] ──> [Creative Look / LUT] ──> [Limiter / Output]
  ```
  - Creative looks and LUTs must never sit on the initial balance node.
  - Grade nodes must preserve dynamic range without clipping black levels below 0% or crushing highlights above 100% (IRE scale).

---

## 3. Audio Loudness & Fairlight Mixing Standards

- **Streaming & Online Delivery (YouTube, Vimeo, Podcast, Web)**:
  - **Integrated Loudness**: Target **-14.0 LUFS** (tolerance $\pm 1.0\text{ LUFS}$).
  - **True Peak**: Maximum **-1.0 dBFS** (prevents inter-sample clipping during lossy AAC/Opus transcode).
- **Broadcast Delivery (EBU R128 / ATSC A/85)**:
  - **Integrated Loudness**: Target **-23.0 LUFS / -24.0 LKFS** (tolerance $\pm 0.5\text{ LUFS}$).
  - **True Peak**: Maximum **-2.0 dBFS**.
- **Dialogue & Ducking Invariants**:
  - Dialogue anchor must average between -18 LUFS and -14 LUFS.
  - Music and atmospheric SFX beds must duck by -12 dB to -18 dB during active dialogue speech.

---

## 4. Final Cut Pro FCPXML DTD Standards

- **Specification**: Conform strictly to Apple FCPXML DTD versions 1.9, 1.10, or 1.11.
- **Resource Binding**: Every `<asset-clip>` in the timeline `<spine>` must reference a valid `<asset id="...">` defined in `<resources>`.
- **Absolute URI Contract**: Asset paths must use standard file URI notation (`file:///Volumes/...` or `file:///path/to/assets/...`).
- **Chapter Markers**: Markers must declare `start`, `duration` (matching frame duration), and `value` (chapter title).

---

## 5. DaVinci Resolve Scripting API Standards

- **Interface**: Automate via official `DaVinciResolveScript` Python API (`dvr.scriptapp("Resolve")`).
- **Bin Hygiene**: Media Pool root folder must maintain structured bins:
  - `01_FOOTAGE` (Primary camera takes)
  - `02_AUDIO` (Multitrack dialogue, foley, voiceover, score)
  - `03_GRAPHICS` (Motion animations, title overlays, SVGs)
  - `04_TIMELINES` (Master cuts, rough cuts, assemblies)
- **Deterministic Persistence**: Scripts must execute `projectManager.SaveProject()` upon completion.
